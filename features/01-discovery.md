# Feature 01: dowser находит живые узлы и открытые порты в периметре (F2)

- **Способность:** по заданному периметру система находит живые узлы, открытые
  TCP-порты и что на них работает (прикладной протокол, баннер, продукт,
  версия). Протокол определяется по номеру порта (быстро) или по содержимому
  ответа (`--detect`). Ни одно соединение не выходит за периметр.
- **Демо:** стенд из контейнеров, часть сервисов на нестандартных портах
  (например, SSH на 2222, HTTP на 8081, FTP на 2121).
  `dowser scan --scope <стенд>` — таблица
  `адрес · порт · протокол · продукт · версия`, стандартные порты опознаны,
  нестандартные — по таблице портов (неверно или пусто).
  `dowser scan --scope <стенд> --detect` — нестандартные порты опознаны
  верно. Адрес вне периметра не сканируется, соединение с ним через `Net`
  даёт `ErrOutOfScope`.

Feature первая, поэтому включает и сквозной каркас: `core`, `store`, `engine`,
`cli`, `cmd/dowser`.

## Контракты

Межмодульные (из `ARCHITECTURE.md`): `engine.Analyzer`, `core.Input`, `core.Net`,
`core.Sink`, `core.AssetView`, `core.ScopeGate`, `engine.Store`, модели
`Asset`, `Service`, `Scope`, `ScanSession`.

Решено:

- `ScopeGate` — конкретный тип в `core`: `NewScopeGate(Scope) *ScopeGate`.
- Живость узла — TCP-connect на частые порты (22, 80, 443, 445, 3389) через
  `Net`. ARP/ICMP отложены до проверяющего метода сырых пакетов в `Net`.
- `Net.Dial` с именем хоста резолвит внутри, проверяет каждый IP и соединяется
  с проверенным IP. DNS-запросы идут через тот же гейт.
- `Service.AppProto` (межмодульное, в `ARCHITECTURE.md`): заполняется всегда.
  Быстрый режим — по таблице портов, `--detect` — по содержимому ответа.
- Флаги независимы: `--ports` — какие порты, `--detect` — как определять.
  Доходят до discovery через его конструктор (`discovery.Config`), не через
  `core`.
- Определение протокола: шаги «ждать → `GET / HTTP/1.0` в то же соединение →
  TLS в новом соединении», остановка на первом совпадении. Номер порта —
  только подсказка о порядке шагов. В быстром режиме выполняется один шаг,
  который подсказывает порт. Таймаут — верхняя граница, чтение завершается
  на первых байтах; читается не больше ~8 КБ.
- Протоколы: SSH, FTP, SMTP, POP3, IMAP, Telnet, MySQL, VNC, rsync (говорят
  первыми); HTTP, Redis, IRC, Elasticsearch (ответ на GET); TLS, HTTPS,
  Kubernetes API (через TLS). Пробы RDP/SMB/PostgreSQL и промышленные
  протоколы — не в v1.
- Признаки ответов на наш GET фиксируются на записанных ответах настоящих
  сервисов (фикстуры с контейнеров), не по документации.
- Локальное: порты по умолчанию — топ-100 TCP из nmap плюс порты из таблицы
  протоколов (Redis, Elasticsearch, Kubernetes, 2375 и др.); таймаут соединения 1 с,
  чтения ответа 2 с; пул — 256 соединений; ID `Asset` = `Addr`, ID `Service` =
  `Addr:Port/Proto`.
