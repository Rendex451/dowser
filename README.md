# dowser

Портативный инструмент сетевого аудита: один статический бинарь на Go.
Находит узлы и сервисы в заданном периметре, определяет протокол, продукт и
версию. Не обращается ни к одному адресу вне периметра.

> Сканируйте только сети, на аудит которых у вас есть разрешение.

## Статус

Готово обнаружение (feature 01): живые узлы, открытые TCP-порты, протокол,
продукт и версия. Дальше по плану: сопоставление версий с CVE и поиск
протоколов без шифрования (feature 02), отчёт в JSON (feature 03).

## Сборка

Нужен Go 1.27+.

```sh
go build -o dowser ./cmd/dowser
```

## Использование

```sh
dowser scan --scope 192.168.1.0/24
dowser scan --scope 10.0.0.5 --scope 10.0.1.0/28 --ports 22,80,8000-8100 --detect
```

| Флаг | Что делает |
|---|---|
| `--scope` | сеть или адрес для аудита, можно повторять; больше 65 536 адресов — ошибка |
| `--ports` | порты для скана; по умолчанию — топ-100 nmap и порты известных сервисов |
| `--detect` | определять протокол по ответу сервиса, а не по номеру порта |

Пример вывода:

```
ADDRESS      PORT       PROTOCOL  PRODUCT  VERSION
172.30.99.2  2222/tcp   ssh       OpenSSH  10.3
172.30.99.3  80/tcp     http      nginx    1.27.5
172.30.99.5  2323/tcp   telnet    -        -
172.30.99.8  13306/tcp  mysql     MariaDB  11.8.9
```

Без `--detect` протокол берётся из таблицы портов: так быстрее, но сервис на
нестандартном порту останется неопознанным. С `--detect` dowser ждёт
приветствия, затем отправляет `GET / HTTP/1.0`, затем пробует TLS.

Опознаются: SSH, FTP, SMTP, POP3, IMAP, Telnet, MySQL/MariaDB, VNC, rsync,
IRC, HTTP, HTTPS, TLS, Redis; среди HTTP-сервисов — Elasticsearch и
Kubernetes API.

## Периметр

Все соединения, включая DNS-запросы, идут через гейт: адрес вне `--scope`
отклоняется до отправки первого пакета. Если DNS-сервер вне периметра, имена
хостов не резолвятся.

## Демо-стенд

```sh
docker compose -f deploy/stand/docker-compose.yml up -d
dowser scan --scope 172.30.99.0/28 --ports 21,80,2222,2323,6379,8081,13306
dowser scan --scope 172.30.99.0/28 --ports 21,80,2222,2323,6379,8081,13306 --detect
docker compose -f deploy/stand/docker-compose.yml down
```

Часть сервисов стенда слушает нестандартные порты, поэтому видна разница
между режимами.

## Тесты

```sh
go test -race ./...
```

Признаки протоколов проверяются на ответах настоящих сервисов, записанных из
контейнеров: `analyzers/discovery/testdata/fixtures`.

## Устройство

Гексагональная архитектура: чистое ядро `core`, оркестратор `engine`,
сменные анализаторы в `analyzers/`, хранилище `store`, вход — `cli`, сборка —
`cmd/dowser`. Подробно — в [ARCHITECTURE.md](ARCHITECTURE.md).

Разработка идёт по модели kickoff → feature → task, см.
[AGENTS.md](AGENTS.md) и `features/`.
